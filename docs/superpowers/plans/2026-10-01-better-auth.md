# Better Auth implementation plan

Approved direction: consistent passkey-first access in later and Highlights, email-code fallback, one-use recovery codes, administrator recovery. User approved autonomous implementation and publishing. Keep data and ownership unchanged. Separate host-only sessions and passkeys, no shared parent-domain cookies/SSO. Existing later password remains an alternative; existing Highlights sessions survive their original expiry, with legacy logout clearing both sessions. Passkey registration requires recent authenticated owner session; support synced passkeys without attachment restriction.

## Tasks
- [ ] Later: extend Better Auth 1.7.6 with matching passkey plugin, hashed 8-digit email OTP (10 min, max five attempts, disable signup), owner guards on all session creation, bounded body/origin checks, per-IP and owner rate limits. Add matching sign-in UI, security page, migrations, focused integration tests. Keep password/reset.
- [ ] Recovery: authenticated recent-session generation of ten cryptographically random one-use codes (128-bit each), hashed at rest, atomic consumption and invalidation on replacement, rate-limited owner-only login via Better Auth session creation. No recovery bypass URL. UI displays codes once without storage/logging; allow download. Regeneration requires fresh sign-in and confirmation; recovery success revokes old sessions. Use same reviewed plugin in both repos.
- [ ] Highlights: install Better Auth/passkey same version; add auth schema and idempotent owner bootstrap, encrypted production secret, fixed APP_ORIGIN; migrate email UI and retain old session compatibility only for unexpired sessions. All protected routes remain owner-gated. Add dedicated security route; drafts/library stay unchanged. Test unknown email, stale sessions, wrong-origin, recovery reuse, signup blocked, malicious registration and no lockout on missing setup.
- [ ] Verify: local tests/typecheck/lint/build, local Worker/browser desktop/mobile email and recovery flows; WebAuthn via available browser capabilities or software authenticator test, clearly report real-device enrollment requirement. Independent security review. Backup live databases before additive migrations; configure secret, migrate and deploy sequentially. Verify live email fallback and unchanged data, passkey endpoint origin/registration gates. Push PRs, CI, merge, retain rollback path.
- [ ] Document: owner recovery runbook including existing identity preservation, credential/session revocation and independent D1/R2 backups; clarify code vs live data. User must personally enroll a passkey in their password manager and retain recovery codes; never do biometric/1Password enrollment on their behalf.

## Review focus
Owner email restrictions across every Better Auth route; legacy-session limits and logout; recent authentication for key/code enrollment; concurrent recovery replay and regeneration; canonical origins through Highlights Pages proxy; offline data access preserved; free Workers CPU behavior. Recovery codes are account access secrets, never source controlled. No paid plans or new identity SaaS.
